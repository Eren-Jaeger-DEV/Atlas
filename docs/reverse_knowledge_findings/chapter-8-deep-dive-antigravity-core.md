# Chapter 8: Deep Dive into Antigravity Core Extension

## Overview
Our continuous reverse engineering of the Antigravity IDE bundle has unveiled the core extension responsible for its flagship AI orchestration, located at `resources/app/extensions/antigravity/package.json`. This extension acts as the central nervous system for the "Jetski" and "Cascade" agents.

## Architectural Secrets

### 1. Workflow and Rule Editors
The core extension explicitly registers custom VS Code editors for Agent orchestration:
- **Workflow Editor**: Activated for markdown files in `.agent/workflows/**/*.md`, `**/.gemini/jetski*/global_workflows/*.md`, and `**/.gemini/antigravity*/global_workflows/*.md`.
- **Rule Editor**: Activated for `.agent/rules/**/*.md`.

This proves that Antigravity IDE natively intercepts and parses markdown files in these directories to render proprietary GUI editors (using the `@exa/agent-ui-toolkit`), replacing the raw text editor with a structured workflow-building interface for the AI agent.

### 2. Native API Proposals
Antigravity utilizes a custom, heavily modified VS Code API feature flag: **`antigravityUnifiedStateSync`**.
This API likely allows the AI agent process (running in the background) to perfectly synchronize its state (e.g., active files, cursor position, selection, terminal output) with the UI in real-time, completely bypassing standard Extension Host latency.

### 3. "Supercomplete" and Hunk Management
The extension defines proprietary keybindings that override standard VS Code behavior:
- `antigravity.prioritized.agentFocusNextHunk` (alt+j)
- `antigravity.prioritized.supercompleteAccept` (tab)

This implies a two-tier AI completion system:
1. Standard inline suggestions (via `inlineCompletionsAdditions`).
2. A more powerful, multi-line "Supercomplete" system that manages diff "hunks" across multiple files simultaneously, allowing the user to quickly alt+j between changes generated by the Cascade agent.

### 4. Direct Competitor Migration
The IDE contains highly specific, aggressive migration commands to pull users from competing AI IDEs directly:
- `antigravity.importCursorSettings` & `antigravity.importCursorExtensions`
- `antigravity.importWindsurfSettings` & `antigravity.importWindsurfExtensions`
- `antigravity.importCiderSettings` (Internal Google IDE migration)

## Embedded Local Search
A configuration flag `antigravity.searchMaxWorkspaceFileCount` (default: 5000) reveals that Jetski computes and caches local vector embeddings for workspaces up to this size. This local embedding engine avoids sending the entire repository to the cloud, opting for local semantic retrieval to save costs and reduce latency.

## Conclusion
The `antigravity` core extension is a masterclass in deep editor integration. By using custom C++ APIs (`antigravityUnifiedStateSync`) and intercepting markdown files to render `@exa/agent-ui-toolkit` graphical workflows, it provides an agent experience that is deeply native rather than feeling like an attached chatbot extension.
